# API Documentation

## External APIs

HTTP/REST over FastAPI. App declared at `services/api/main.py:5`
(`FastAPI(title="ticket-triage", version="0.4.2")`); routers registered at
`main.py:6-7`. OpenAPI/Swagger is auto-generated by FastAPI at `/openapi.json`,
`/docs`, `/redoc` (framework defaults; not customised or disabled).

Base URL in local development: `http://localhost:8080`
(`uvicorn services.api.main:app --reload --port 8080`).

**No middleware is registered** — no CORS, no GZip, no request-id, no rate
limiting, no exception handlers. Auth is per-route via
`Depends(require_token)`.

### `POST /v1/tickets` — accept a ticket

- Source: `services/api/routes/tickets.py:18-22`
- Auth: **required** (`require_token`)
- Success status: **202 Accepted**
- Request body — `TicketIn` (`schemas.py:6-11`):

| Field | Type | Constraint | Default |
|---|---|---|---|
| `tenant_id` | string | `min_length=1`, `max_length=64` | — (required) |
| `subject` | string | `min_length=1`, `max_length=512` | — (required) |
| `body` | string | **no length limit** | — (required) |
| `channel` | string | **no enum validation** at the schema level | `"portal"` |
| `locale` | string | none | `"ko-KR"` |

- Response — `TicketOut` (`schemas.py:14-17`):
  `{"ticket_id": "<uuid4 hex>", "accepted_at": "<ISO-8601 UTC>", "queued": true}`
- Behaviour: mints `uuid.uuid4().hex`, `LPUSH`es
  `{ticket_id, tenant_id, subject, body, channel, locale}` onto the Redis list,
  returns immediately.
- Failure modes: `401` missing/malformed bearer, `403` wrong token, `422`
  Pydantic validation. **A Redis outage produces an unhandled exception → 500**,
  and `queued: true` is returned unconditionally without confirming the push.
- Notes: the ticket is **not persisted** anywhere; `queued` is hard-coded, not
  measured.

### `GET /v1/tickets/{ticket_id}/triage` — read the triage result

- Source: `services/api/routes/tickets.py:25-29`
- Auth: **required**
- Path param: `ticket_id` (string, unvalidated)
- Response — `TriageOut` (`schemas.py:20-25`):
  `{"ticket_id": str, "category": str, "priority": int (1-4), "sentiment": float (-1..1), "assignee_group": str}`
- Errors: `404 {"detail": "triage result not ready"}`
- **Behaviour warning:** reads the in-process dict `_seen`
  (`routes/tickets.py:15`), which is written **only** by the reclassify
  endpoint. A ticket submitted through `POST /v1/tickets` returns 404
  permanently; `triage_results` in the database is never queried. Under a
  multi-process deployment the result is additionally non-deterministic. See
  `architecture.md` § Data Flow.
- **No tenant-ownership check** — any valid token can read any ticket id.

### `POST /v1/tickets/{ticket_id}/reclassify` — re-run triage synchronously

- Source: `services/api/routes/tickets.py:32-52`
- Auth: **required**
- Path param: `ticket_id`; Request body: `TicketIn` (same schema as ingest — the
  caller supplies the content to reclassify; the server does not look up the
  original ticket, because it never stored one)
- Response: `200` `TriageOut`
- Behaviour: builds a `Ticket`, runs `TriageEngine.classify` **in the request
  thread**, caches the result in `_seen[ticket_id]`, returns it. Redis and the
  database are not touched.
- Failure modes: `401`/`403`/`422` as above; **an unrecognised `channel` value
  raises `ValueError` in `Channel(payload.channel)` (`tickets.py:39`) → 500**.
- **No tenant-ownership check.**

### `GET /healthz` — liveness

- Source: `services/api/routes/health.py:8-10`
- Auth: **none**
- Response: `200 {"status": "ok"}` — static; touches no dependency.

### `GET /readyz` — readiness

- Source: `services/api/routes/health.py:13-15`
- Auth: **none**
- Response: `200 {"status": "ok", "queue_depth": <int>}` where `queue_depth` is
  `LLEN triage:pending`.
- **Behaviour warning:** it calls Redis on every invocation and there is no
  try/except, so an unreachable Redis surfaces as an unhandled `500` rather than
  a "not ready" body. The endpoint can never report degraded readiness in its
  payload. It also exposes queue depth without authentication.

### Authentication

`services/api/deps.py:6-13` — `require_token(authorization: str = Header(...))`:

1. Requires the `Authorization` header to start with `Bearer ` → else
   `401 "missing bearer token"`.
2. Compares the remainder to `settings.api_token` → else
   `403 "invalid token"`.

Properties to know: it is a **single shared static token** for all tenants; the
comparison is a plain `!=` (not constant-time); the value defaults to the
literal `"dev-token"` when `API_TOKEN` is unset (`config.py:10`); and no route
correlates the token with `payload.tenant_id`, so **the API provides no tenant
isolation**.

## Internal APIs

### Queue contract — `services.api.queue` ↔ `services.worker.main`

The only inter-service contract. Redis list, JSON-encoded, FIFO
(`LPUSH` producer / `BRPOP` consumer).

- Key: `settings.queue_key`, default `triage:pending` (`config.py:9`)
- Producer: `services/api/routes/tickets.py:21`
- Consumer: `services/worker/main.py:33-43`

| Function | Signature | Behaviour |
|---|---|---|
| `push` | `push(payload: dict) -> None` | `LPUSH key json.dumps(payload)` (`queue.py:11-12`) |
| `pop` | `pop(timeout: int = 5) -> dict \| None` | `BRPOP key timeout`; returns the decoded payload or `None` on timeout (`queue.py:15-17`) |
| `depth` | `depth() -> int` | `LLEN key` (`queue.py:20-21`) |

Message shape (implicit — **there is no schema on either side**):

```json
{
  "ticket_id": "3f2a…",   // required; consumer does item["ticket_id"]
  "tenant_id": "acme-corp", // required
  "subject": "…",           // required
  "body": "…",              // required
  "channel": "portal",      // optional, consumer defaults to "portal"
  "locale": "ko-KR"         // produced but IGNORED by the consumer
}
```

Contract hazards:

- A missing `ticket_id`/`tenant_id`/`subject`/`body` raises `KeyError`
  (`worker/main.py:37-40`) and **terminates the worker process**.
- An unrecognised `channel` raises `ValueError` at `worker/main.py:41` — same
  effect.
- `locale` is sent by the API but never read by the worker, so worker-side
  classification always uses the `Ticket` default `ko-KR` (`models.py:31`).
- No ack/retry/dead-letter: `BRPOP` removes the message before processing, so
  any failure loses the ticket permanently.

### Library API — `packages.triage_core`

Public surface re-exported at `packages/triage_core/__init__.py`:
`Ticket`, `TriageResult`, `Priority`, `TriageEngine`.

| Symbol | Signature | Notes |
|---|---|---|
| `TriageEngine.__init__` | `(llm_client=None, max_body_chars: int = 4000)` | `llm_client` is `None` at every call site (`routes/tickets.py:14`, `worker/main.py:29`), so the LLM path is dead. |
| `TriageEngine.classify` | `(ticket: Ticket) -> TriageResult` | Pure and deterministic; the only unit-tested surface. |
| `TriageEngine._category / _sentiment / _priority` | private | See `architecture.md` § T3. |
| `store.make_session_factory` | `(db_url: str) -> sessionmaker` | Calls `Base.metadata.create_all(engine)` as a side effect (`store.py:31`). |
| `store.TicketRow` | table `tickets` | **Never instantiated anywhere — dead schema.** |
| `store.TriageRow` | table `triage_results` | Written by the worker (`worker/main.py:46-54`); **read by nobody**. |

### Notification adapter — `services.worker.notifier.Notifier`

`Notifier(slack_webhook: str = "", topic_arn: str = "")`, method
`notify(result: dict) -> None` where `result` is
`{"ticket_id": str, "group": str}` (`worker/main.py:56`).

- Slack: `httpx.post(webhook, json={"text": f"triage: {result}"}, timeout=10)`
  (`notifier.py:21-23`). Synchronous, inside the consumer loop, no retry.
  Enabled by the `SLACK_WEBHOOK` env var (`worker/main.py:30`).
- AWS SNS: `_sns.publish(TopicArn=..., Message=str(result))` (`notifier.py:19-20`).
  **Unreachable** — the worker never passes `topic_arn`. The module-level
  `boto3.client("sns")` (`notifier.py:10`) still executes on import.

## Contracts & Schemas

| Contract | Type | Location | Shared with |
|---|---|---|---|
| `TicketIn`, `TicketOut`, `TriageOut` | Pydantic v2 models | `services/api/schemas.py` | HTTP clients only |
| `Ticket`, `TriageResult`, `Priority`, `Channel` | Python dataclasses / enums | `packages/triage_core/models.py` | API + worker (in-process) |
| Queue message | **untyped JSON dict** | implicit; `queue.py` ↔ `worker/main.py` | API ↔ worker (cross-process) |
| `tickets`, `triage_results` | SQLAlchemy declarative tables | `packages/triage_core/store.py` | worker (write only) |
| OpenAPI 3.1 document | generated | `/openapi.json` at runtime | HTTP clients |

There is **no committed schema file** — no OpenAPI snapshot, no JSON Schema, no
protobuf, no GraphQL SDL, and no migration files. The only versioned contract
artefacts are the Python type declarations themselves. Note the DTO/domain
overlap: `TicketIn` and `Ticket` describe the same concept with different
validation rules (`TicketIn.body` is unbounded while the engine truncates at
4000 chars, and `TicketIn.channel` is a bare `str` while `Ticket.channel` is a
`Channel` enum) — the mismatch is where the 500s described above originate.
