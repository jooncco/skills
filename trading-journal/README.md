# trading-journal

하루치 매매를 복기 노트로 만든다.

```
/trading-journal 2026-09-07
```

바탕화면의 MT5 스냅샷과 거래 내역을 대조해 거래에 번호를 매기고, 진입·청산 화살표가
보이도록 잘라낸 차트 이미지를 붙여 마크다운 일지를 저장한 뒤, 네이버 카페 글쓰기
화면을 채운 채로 멈춘다.

## 산출물

```
<journal_dir>/
├── 2026-09-07-XAUUSD-매매복기.md
└── images/
    ├── 2026-09-07-01.png     # 거래 1건당 1장
    └── …
```

일지 구조. `근거` 칸과 `오답노트` 는 **비어 있다** — 스킬이 채우면 그건 복기가 아니라
추측이다. H1 제목도 넣지 않는다(Obsidian 이 파일명을 제목으로 표시하므로 중복된다).

```
> 13건 · 8승 5패 · 합계 +84.2
> 계좌 hantec · 작성 2026-09-07 23:40 KST

## 매매 내역
| # | 진입시각 | 진입가 | 방향 | 홀딩 | 청산시각 | 청산가 | 손익 | 근거 |

## 차트
### #1   ![](images/2026-09-07-01.png)
…

## 오답노트
```

## 좌표를 사람이 찍지 않는다

이 스킬의 핵심.

스크린샷의 가격 라벨을 검출된 그리드선에 손으로 짝지으면, 한 칸 틀렸을 때 배지가
**통째로** 밀린다. 그런데 그림은 여전히 멀쩡해 보인다 — 조용히 틀리는 실패이고, 일지에
박히고 나면 원본 없이는 검증할 방법이 없다.

그래서 축 눈금(분/px, 가격/px — 둘 다 축에서 그냥 읽힌다)만 받고, **오프셋은 MT5 가
이미 그려둔 체결 화살표에서 역산한다.** 매수 화살표 `(58,130,247)`, 매도
`(221,83,62)`. 각 (마크, 화살표) 쌍이 자기가 함의하는 오프셋에 투표하고, 가장 많이
겹치는 값을 취한다 — 틀린 짝은 흩어지고 맞는 짝만 쌓인다.

렌더할 때마다 배지가 실제 화살표 위에 있는지 다시 검증해서 보고한다:

```
✓ 2026-09-07-04.png  #4  matched 2/2  dy 21.1px
```

`matched` 가 차지 않으면 그 스냅샷에 그 거래가 없거나 눈금이 틀린 것이다. 진행하지
않는다.

## 스크립트

| 파일 | 하는 일 |
|---|---|
| `scripts/fetch_trades.py` | 플랫폼 dashboard API 에서 KST 하루치 라운드트립을 받아 시간순 채번. sync 지연도 같이 경고한다 |
| `scripts/probe_axes.py` | 스크린샷의 그리드 주기 검출. 대시가 성겨 임계값으로는 안 잡히므로 주기·위상으로 찾는다 |
| `scripts/annotate_chart.py` | 크롭 + 번호 배지. 축 역산, 배지 충돌 회피, 볼린저 밴드가 프레임에 들어올 때까지 세로 확장 |
| `scripts/build_specs.py` | 거래번호만 주면 스펙 생성부터 렌더까지. 축은 스냅샷당 한 번 풀고 재사용한다 |

배지는 MT5 화살표와 **같은 색**이고(파랑=매수 체결, 빨강=매도 체결), 진입은 채운 원,
청산은 속 빈 원이다. 매도 거래의 진입 배지가 빨간 것은 정상이다.

## 필요한 것

- **macOS** — 바탕화면 스냅샷, 시스템 한글 폰트를 쓴다
- **[`uv`](https://docs.astral.sh/uv/)** — 스크립트가 PEP 723 인라인 의존성으로
  Pillow 를 가져온다. 가상환경을 따로 만들 필요 없다
- **MT5 모바일 스냅샷** — 매매 History 1장 + 진입·청산 화살표가 찍힌 캔들 차트 여러 장.
  그날 거래가 전부 덮여야 한다
- **[billion-dollar-baby](https://github.com/jooncco/billion-dollar-baby) 백엔드**가
  `127.0.0.1:8000` 에 떠 있을 것. 거래 숫자는 스냅샷 OCR 이 아니라 여기서 온다

## 설정

`~/.claude/trading-journal.json`

```json
{
  "journal_dir": "…/notes/PROJECT/2026-07-BILLION-DOLLAR-BABY",
  "account_id": "hantec",
  "api": "http://127.0.0.1:8000",
  "cafe_url": "https://cafe.naver.com/…"
}
```

`journal_dir` 은 매 실행마다 기본값으로 제시되고, 다른 경로를 고르면 갱신된다.

## 게시

로그인된 Chrome 으로 카페 글쓰기 화면을 채우고 **등록 직전에 멈춘다.** 계정 정보를
다루지 않고, 나가기 전에 사람이 눈으로 확인할 수 있다. 등록 버튼은 사람이 누른다.
