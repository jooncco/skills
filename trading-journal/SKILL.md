# 매매일지 작성

인자: `$ARGUMENTS` (날짜 `YYYY-MM-DD`. 없으면 오늘 KST 날짜)

산출물은 **일지 1개 + 차트 이미지 여러 장**이고, 마지막에 네이버 카페 글쓰기
화면을 채운 채로 멈춘다. **등록 버튼은 절대 누르지 않는다.**

---

## 0. 스냅샷부터 확인한다 — 다른 어떤 것보다 먼저

아직 아무것도 읽지 말고 사용자에게 먼저 묻는다:

> 바탕화면에 오늘 매매 스냅샷을 올려두셨나요? 두 종류가 필요합니다:
> - **매매 History** — 진입·청산·손익이 보이는 목록 화면
> - **캔들 차트** — 포지션 진입/청산 화살표가 찍힌 차트. 그날 거래가 전부 덮이게 여러 장
>
> 준비되면 "네"라고 답해주세요.

확인을 받기 전에는 `~/Desktop` 을 뒤지지 않는다. 사용자가 아직이라고 하면 거기서
멈춘다 — 스냅샷 없이 만든 일지는 표만 있고 근거가 없어서 쓸모가 없다.

확인 후 목록을 뽑고, 최근 것부터 보여주며 어느 것이 이번 일지 대상인지 맞춘다:

```bash
ls -lt ~/Desktop/*.{PNG,png,JPG,jpg,jpeg,HEIC} 2>/dev/null | head -30
```

## 1. 저장 위치 확인 — 매 실행마다 묻는다

```bash
cat ~/.claude/trading-journal.json 2>/dev/null || echo '{}'
```

키: `journal_dir`, `account_id`, `api`, `cafe_url`.

**실행할 때마다 저장 위치를 확인받는다.** `AskUserQuestion` 으로 설정된 경로를
기본 선택지로 제시하고, 사용자가 다른 경로를 고르거나 직접 입력할 수 있게 한다:

- 설정된 `journal_dir` — "이번에도 여기" (기본)
- 다른 경로 직접 입력

파일을 쓰기 전에 확인이 끝나야 한다. 일지는 조용히 엉뚱한 폴더에 생기면 찾기
어렵고, 사용자가 날짜별로 다른 볼트에 넣고 싶을 수도 있다.

새 경로를 고르면 `~/.claude/trading-journal.json` 의 `journal_dir` 을 그 값으로
갱신한다 — 다음 실행의 기본값이 된다.

`journal_dir` 이 아예 없으면 기본 선택지 없이 경로를 묻는다.

기본값: `api` = `http://127.0.0.1:8000`,
`cafe_url` = `https://cafe.naver.com/f-e/cafes/21796352/menus/139?viewType=L`.

## 2. 거래 내역 — 숫자는 DB에서, 대조는 스냅샷으로

```bash
.claude/skills/trading-journal/scripts/fetch_trades.py <DATE> --account <ACCOUNT>
.claude/skills/trading-journal/scripts/fetch_trades.py <DATE> --account <ACCOUNT> --json
```

시각·가격·손익은 **플랫폼 dashboard 엔드포인트가 정답**이다. 스냅샷 OCR 로 표를
만들지 않는다.

그 다음 **History 스냅샷을 읽어 건수와 손익 합계를 대조한다.** 어긋나면 표를 고치지
말고 사용자에게 알린다 — 대개 sync 가 밀렸거나 다른 계좌가 섞인 것이고, 둘 다
조용히 덮어쓸 성질이 아니다. `fetch_trades.py` 가 `warnings` 를 뱉으면 그대로 전한다.

채번은 `opened_at` 오름차순 1번부터. 이 번호가 표·이미지·배지에서 **모두 같아야**
한다.

## 3. 스냅샷 ↔ 거래 매핑

차트 스냅샷을 하나씩 Read 해서 x축 시간 라벨 범위를 적는다. MT5 차트는 **브로커
시각**이라 KST 와 다르다.

**시차를 추정하지 말고 유도한다.** 첫 스냅샷에서 축 라벨 범위를 읽고, 그 창에 들어갈
거래를 표에서 찾아 화살표 위치와 맞춰본다. Hantec(UTC+3)이면
`chart_tz_offset_min = -360` (= (3 − 9) × 60). 같은 브로커 스냅샷은 이 값을 공유한다.

각 스냅샷에 어떤 거래 번호가 들어가는지 표로 정리해 사용자에게 보여준다. 어떤 거래도
덮이지 않으면 **그 사실을 말한다** — 스냅샷이 빠진 것이고, 조용히 넘기면 일지에 근거
없는 행이 남는다.

## 4. 축 눈금 읽기

스냅샷마다 그리드 주기를 뽑는다:

```bash
.claude/skills/trading-journal/scripts/probe_axes.py ~/Desktop/IMG_XXXX.PNG --dump-axis /tmp/ax
```

좌표는 **원본 픽셀**로 나온다. (Read 로 이미지를 볼 때 안내되는 "×1.28" 배율은 눈으로
좌표를 찍었을 때만 쓴다. 둘을 섞으면 배지가 통째로 어긋난다.)

필요한 건 네 숫자뿐이다 — **라벨을 그리드선에 짝지을 필요는 없다**:

| 값 | 어디서 |
|---|---|
| 그리드선 1칸당 분 | 축 라벨 간격(분) ÷ 라벨 사이 그리드선 개수 |
| 세로 그리드 주기 px | `probe_axes` 의 `vertical [BEST] period` |
| 그리드선 1칸당 가격 | 가격 라벨 간격 |
| 가로 그리드 주기 px | `probe_axes` 의 `horizontal [BEST] period` |

`--dump-axis` 가 만든 `axis_time.png` / `axis_price.png` 를 Read 해서 라벨 간격을 읽는다.

> 가로 그리드가 **배주기**로 잡히는 경우가 있다. `probe_axes` 가 반주기 후보를 같이
> 출력하니 **축에 보이는 라벨 개수와 맞는 쪽**을 쓴다. 틀려도 5번에서 걸린다.

## 5. 차트 이미지 — 오프셋은 MT5 화살표에서 역산된다

`shots.json` 을 쓰고 한 번에 렌더한다:

```json
{
  "chart_tz_offset_min": -360,
  "chart_area": {"x0": 4, "y0": 440, "x1": 995, "y1": 2185},
  "shots": [
    {"src": "~/Desktop/IMG_9669.PNG", "trades": [4,5,6,7], "grid": [8, 144, 2.50, 120]}
  ]
}
```

`grid` = `[분/그리드, 세로주기px, 가격/그리드, 가로주기px]`.

```bash
.claude/skills/trading-journal/scripts/build_specs.py \
  --trades /tmp/trades.json --shots /tmp/shots.json --out-dir <journal_dir>/images
```

**거래 1건당 이미지 1장**이 나온다 (`<날짜>-04.png` = 4번 거래). 표의 행과 1:1 로
맞아떨어진다. 한 스냅샷에 여러 거래가 있어도 축은 **스냅샷당 한 번** 풀고 재사용하니
컷마다 해가 흔들리지 않는다.

마크·캡션·파일명은 **거래표에서 그대로 파생**되므로 표의 가격과 그림의 배지가 어긋날
수 없다. 축 오프셋은 MT5 가 이미 그려둔 화살표에서 역산한다 — 라벨을 그리드선에
잘못 짝지어 전체가 한 칸 밀리는 실패가 원천적으로 없다.

출력의 `matched a/b` 와 `dy` 를 확인한다:

- `matched` 가 전부 맞고 `dy` 가 **20px 이내** → 정상
- 미매칭이 있거나 `⚠` → **그 스냅샷에 그 거래가 없거나 `grid` 값이 틀렸다.**
  진행하지 말고 4번으로 돌아간다
- `dy` 는 배지 중심과 화살표 팁의 기하학적 차이라 10px 안팎은 정상이다

**그리고 렌더된 PNG 를 최소 한 장은 Read 해서 눈으로 확인한다.** 숫자가 통과해도
크롭 범위가 엉뚱할 수 있고, 그건 사람 눈에만 보인다.

배지는 **MT5 화살표와 같은 색**(파랑=매수 체결, 빨강=매도 체결)이고, 진입은 채운 원,
청산은 속 빈 원이다. 매도 거래의 진입 배지가 빨간 것은 정상이다.

파일명은 `<날짜>-<거래번호>.png`, 위치는 `<journal_dir>/images/`.

크롭 규칙 (`pad`):

- 최소 25분 구간 (`min_minutes`) — 짧은 스캘핑도 앞뒤 맥락이 남는다
- **볼린저 밴드가 프레임에 들어올 때까지 세로를 넓힌다** (`fit_colors`,
  기본 보라 `[175,66,235]` + 흰 `[254,255,255]`). 거래 자신의 가격폭에만 맞추면
  밴드 터치 진입이었을 때 정작 판단 근거가 잘려나간다. 극단 스파이크는
  5·95 분위(`fit_quantile`)로 잘라낸다
- 세로:가로 `max_aspect` 1.6 을 넘지 않는다. 차트 끝에 걸리면 좁히지 말고
  창을 **밀어서** 폭을 유지한다
- **헤더 띠는 넣지 않는다.** 일지의 `### #4` 소제목과 표 행이 바로 위에 있어
  이미지에 다시 굽는 것은 화면만 잡아먹는다

## 6. 일지 조립

`reference/journal-template.md` 를 채운다. 플레이스홀더:

| 자리 | 채울 것 |
|---|---|
| `{ACCOUNT}` | 계좌 |
| `{N}` `{WINS}` `{LOSSES}` `{NET}` | 건수, 승/패, 합계 손익 |
| `{WRITTEN_AT}` | 작성 시각 |
| `{TRADE_TABLE}` | `fetch_trades.py` 출력 그대로 — **`근거` 칸은 비워 둔다** |
| `{CHART_SECTIONS}` | 거래별 `### #4` 소제목 + `![](images/….png)`, 표 순서대로 |

**H1 제목은 넣지 않는다.** Obsidian 은 파일명을 노트 제목으로 표시하므로
`# 2026-09-07 XAUUSD 매매복기` 를 본문에 두면 화면에 제목이 두 번 나온다. 날짜와
종목은 이미 파일명에 있다. 카페에 올릴 때의 제목도 본문이 아니라 제목 칸에 넣는다.

**`근거` 와 `오답노트` 는 사용자가 쓰는 자리다. 채우지 않는다.** 오늘 무엇을
배웠는지 짐작해서 적어 넣는 순간 그건 사용자의 복기가 아니라 내 추측이 된다.
사용자가 명시적으로 분석을 요청하면 그때 별도로 답하고, 일지에는 사용자가 승인한
문장만 들어간다.

저장: `<journal_dir>/<날짜>-<종목>-매매복기.md`
(예: `2026-09-07-XAUUSD-매매복기.md`)

같은 이름이 이미 있으면 **덮어쓰기 전에 읽고 물어본다.** 사용자가 이미 `근거` 와
`오답노트` 를 채워뒀을 수 있고, 그건 이 스킬이 되살릴 수 없는 유일한 내용이다.

## 7. 네이버 카페 게시 — 채우기까지만

`claude-in-chrome` 스킬을 먼저 로드한다. 사용자의 로그인된 Chrome 을 그대로 쓰므로
계정 정보는 다루지 않는다.

1. `cafe_url` 을 새 탭으로 열고 글쓰기 화면으로 이동
2. 제목: `<날짜> <종목> 매매복기`
3. 본문: 일지 내용. SmartEditor 는 마크다운을 렌더하지 않으므로 표는 붙여넣은 뒤
   모양이 깨졌는지 확인하고, 깨졌으면 사용자에게 알린다
4. `images/` 의 이미지를 순서대로 첨부. 에디터가 업로드를 막으면 억지로 우회하지
   말고 경로를 알려주며 수동 첨부를 안내한다
5. **거기서 멈춘다.** 등록 버튼은 누르지 않는다. 화면이 준비됐다고 알리고,
   사용자가 검토 후 직접 등록하게 한다

게시는 외부로 나가는 행위다. 사용자가 "올려줘" 라고 다시 말해도 이 스킬은 등록까지
하지 않는다 — 채워둔 화면을 확인시키고 사용자가 누르게 한다.

## 실패했을 때

- **백엔드 불통** → `fetch_trades.py` 가 그렇게 말한다. 스냅샷 OCR 로 대체하지 말고
  백엔드를 띄우도록 안내한다
- **sync 지연** → 경고를 그대로 전하고, 표가 불완전할 수 있음을 일지 상단에 남긴다
- **배지가 안 맞음** → 캘리브레이션 문제다. 렌더를 지우고 4번으로 돌아간다
- **거래는 있는데 차트 스냅샷이 없음** → 표는 완성하고, 어느 번호가 이미지 없이
  남는지 명시한다. 없는 이미지를 지어내지 않는다
